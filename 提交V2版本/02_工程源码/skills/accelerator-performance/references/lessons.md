## 已获退役授权的旧模型引擎

资源优化先核对当前用户指定的模型与退役优先级。若旧模型专用引擎已不属于
目标且允许关闭，优先评估该引擎，而非缩减目标模型的计算或缓存能力。
PG2L100H CPU75 案例中旧 H128 sparse evaluator 仍占 1,240 LUT、815 FF、
6 APM 和 1 DRM；2026-10-19 用户指定后续资源优化优先关闭它。官方 Pikafish
的 Stage A gather、Stage B dense MAC 和权重缓存必须保留。该记录只是后续
优先级的历史记录，不能把子模块统计直接当成移除后的整机净节省。
实施时复核共享 DDR 仲裁、MMIO 读回和驱动能力探测，再做整机资源、时序及
实际目标模型验收。其他工程重新确认其本地授权和兼容范围。

随后 CPU80 候选将 ENABLE_H128_SPARSE 设为 0，旧窗口读零、写无效，
无 IRQ/DDR 请求；通用源码仍允许显式启用历史引擎。启用/禁用双配置仿真
核对 32 个窗口寄存器及闲置周期，dense 七组周期和 gather 3538 周期一致，
官方 Stage A/B 和 64 行权重缓存保留。第二候选整机综合 42298 LUT、32313 FF、
119.5 DRM、171 APM，包含 CPU 同时修改，不能把全部净差归因于 H128。
此记录写入时完整 CPU121、SoC23 和 Windows11 组检查通过，原生全角 STA、
实板 MMIO 及官方模型性能仍待验收。FP8/卷积前端沿用基线关闭状态。

## CPU75 上板：提频收益与整模型目标分别验收

2026-10-19，PG2L100H 的 75 MHz CPU / 49.5 MHz MAC 候选按原规模通过
8 个上下文、3×2 线程共 384 作业、400 驻留权重作业和 3072 gather lane。
官方 Pikafish FC0 的 16 bucket/96 case/384 作业，以及严格驱动下的 1024 作业
通过。固定 10 FEN、原预存黄金向量和只读 49.5 MHz CLINT 计时的完整 NNUE
冷/暖各 40 个样本均值为 20.357/19.340 ms，100 次整数结果一致、400 Stage B
作业、fallback=0、mismatch=0；10 ms 目标仍未达到。

此前同工具/向量的 70.875 MHz 记录为 21.151/20.120 ms，但不是同会话 A/B，
应按历史比较报告约 3.8% 改善，不声称严格控制变量或推导 YOLO 30 fps。
CPU CoreMark 3+1 通过、均值 395.836638 也不能替代上述模型和并发检查。

## NNUE：大比例开销在模型搬运和特征处理

历史一次 683 节点、190 次 NNUE 的搜索 profile：搜索 32,728 ms，transform
21,944 ms（67.1%），propagation 3,808 ms；其中 FC0 host 3,332 ms，属于
propagation，不应重复相加。实际 FC0 MAC 总约 176.73 ms。
因此单纯缩短乘加并不解释整体搜索收益。
10-09 发现本工程 Linux jiffies 低估时间；以上历史 host/profile 读数与占比未
独立校准，需重测后再用于绝对延迟或瓶颈比例。硬件周期另按实际频率校验。

候选 Stage A 用 PFF1 描述符直接读取 S8 特征行，模 65536 更新 S16 accumulator；
Stage B 给 fd 保存不可变 593,920 B 模型快照。旧“resident”只驻留用户 shadow，
旧 ioctl 每 FC0 tile 仍复制 8 KiB 权重。优化需要改变真正的传输，而非变量命名。
预热排除十次，并单独说明首次模型注册成本；与 YOLO 交错时需测模型恢复和排队。
截至 10-08，这些候选没有取得完整 NNUE 板上平均时间，10 ms 仍是目标。

## DMA 与 LUT 的组合优化

10-05 输出 DMA 修复最大 S16 作业 12 位地址回绕和每字空拍；紧凑输出布局将
8,192×32 SRAM 减为 4,096×32，默认裸核心布局保留。
同组六个小特征块、19 个作业：646,929 → 613,721 周期。

10-06 case 选择共享 sum/bias，当前 lane 写出时准备下一 lane；128 B 激活缓存
改成四个 32×8 银行。最终 19 作业为 576,996 周期（49.5 MHz 折算 11.6565 ms），
37,954 个 INT32 结果一致，读/写 720,544/151,816 B 不变。
整机映射 37,475 → 34,308 LUT（−8.451%），29,955 → 28,932 FF；
195 APM/150 DRM 不变，分布式 RAM 1,067 → 1,083。
one-hot 选择器反而用 38,635 LUT，被拒绝。组合候选最终时序未通过，收益是
仿真/映射范围内的结果，不能作为板端或生产配置的验收。

## 30 fps 的数据供给瓶颈

同模型 60 个 Conv、523,033,600 MAC、6,956 ABI1 作业；26 种尺寸的周期加权
约 1,008.005 ms。不是完整模型执行，未包含 CPU 打包、合并、SiLU/Detect、采集等。
76,830,288 B/帧逻辑流量：权重 49.3%，激活 29.7%，INT32 写回 20.9%。
首层小通道卷积约占该加权周期预算 16.3%。后续优先研究权重复用、低通道利用率
和部分和驻留；这些策略尚未实现。

仿真状态加权：输入装载 25.7%、权重 42.7%、核心等待 20.4%、输出 11.1%。
RAM 模型每两拍返回一拍，8-beat 请求与数据合计 18 周期；不能直接外推板上 DDR。
核心等待还含准备与后处理。现有 128 MAC/拍、49.5 MHz 的纯计算下界约 82.55 ms；
该分块的串行 32 位路径流量下界约 388.03 ms。即使理想每层权重只读一次，
剩余流量下界仍约 205.614 ms。这些下界不能当作帧率实测。

10-05 四角时序基线 CRAM，匹配 NNUE/语音候选 Linux；12 项载荷哈希通过。
10 个局面，每冷/热阶段排除 10 次预热后 200 样本，CPU/verify/严格加速整数 tuple
通过；fused=0、Stage B fallback/mismatch=0。两个 fd、400 并发作业的模型
不可变/恢复、ABI3 卷积和 384 作业调度通过。未执行完整 UCI 搜索或 YOLO 图。

CPU 原 jiffies 冷/热读数 460.380/391.000 ms，严格加速 44.460/41.600 ms，
由此得到的 10.355×/9.399×全部撤回。sleep 5 的 host 时间 8.25 秒，
CLINT 记录 1.436778 秒时 Linux 只记 1.004 秒。4 ms 分辨率不能解释该偏差，
不能按统一比例换算不同负载；程序 TARGET_MISS/退出 2 不构成有效计时验收。

gather ioctl 原读数 12.200/10.980 ms、FC0 host 8.140 ms 及相减的其余
host 24.120/22.480 ms 均无效；小作业 legacy/resident 3.960/1.440 ms 同样撤回，
权重源流量 8192/0 B 仍有效。gather 与 FC0 硬件周期按 49.5 MHz 合计
2.687/2.381 ms，属于完整 host 工作的子集，不能再次相加。

只读 CLINT 基准 wrapper 保留原 O3/LTO 参数，QEMU 整数比对与无隐式回退检查
通过；诊断 rootfs/DTB 已准备、未写卡。随后从 bootloader 将同一 O3/LTO 计时程序
热加载到 DTS 预留 DDR 空闲区，Linux 只读 mmap 回读 SHA-256 通过后重测。
同一工作量的 CLINT CPU 冷/热均值 706.939/593.275 ms；严格加速
64.799/61.935 ms，倍率 10.910×/9.579×，整数通过且无 fallback/fused/mismatch。
10 ms 未达到；30 fps 和完整 UCI 搜索未测。

其余未拆分 host 34.167/33.212 ms；硬件周期仅占 2.692/2.383 ms，约 4.15%/3.85%。
这些硬件时间是 host 子集；先细分其余 host，再评估拷贝/提交和中间数据驻留。

## 2026-10-09：范围检查与递增 DMA 地址

性能工程后续试验保留公开的 Cin/Cout 16 位检查，收窄内部配置，启动时缓存合法
kernel 的标量总数；输入 DMA 从每次计算 pixel×tiles 改为接受像素时增加缓存步长。
计数宽度需覆盖宽高输入的完整范围；地址仍使用已校验的整张量范围，不能以
低位截断取代拒绝高位非法输入。4 KiB 与通道 tile 的地址、尾字节、错误恢复须
独立检查；本例 843,296 配置、12 组地址/1,490 tap 与最大 102,400 像素通过。

局部带串行输入 wrapper 的配置探针节省 21 LUT，而同版整机配置单独改动反而
增加 21 LUT（34,329），仅省 2 APM。与地址递增组合才得到 34,206 LUT、191 APM、
150 DRM，较旧 34,308/195 减少 102 LUT/4 APM，周期和字节不变。
另外平衡加法/饱和改写虽整数通过，却增加 23 LUT；去掉未使用缓存复位的
局部试验没有资源收益。编码或局部资源不能替代整机资源证据。
随后完整冷构建全部时序满足，慢 setup/hold +0.862/+0.137 ns、快角
+3.081/+0.100 ns，331 条 DDR 实际绑定及 17 个时钟核对。匹配新位流 JTAG
上板、DDR/SD Linux、窗口、ABI3、常驻 400 并发、8 context/384 调度通过。
真实权重六块各三次、57 作业的部分和与最终量化通过，实际 DDR 每轮硬件
1,080,982 周期（21.838 ms）。CLINT C probe total 6,034.667 ms 含 CPU 打包、
合并和黄金比较/CRC，不能称为整图推理；其中打包 1,751.010 ms、提交
412.162 ms、合并 1,041.896 ms、比较/CRC 2,798.144 ms。先明确测量边界再
决定硬件计算、CPU 展开或数据复用的优化优先级。

同样 N=200 的新候选 CLINT NNUE 冷/热均值 65.458/61.042 ms，整数通过，
fused/fallback/mismatch=0，resident=1；旧基线 64.799/61.935 ms，不能从
一次冷稍慢/热稍快对照宣称稳定的延迟收益。本轮 gather ioctl 17.629/16.134 ms、
FC0 host 12.605/12.547 ms、未拆分 host 35.224/32.361 ms；硬件子集只有
2.693/2.405 ms。10 ms、完整图/30 fps 未达到。确认 GUI 真正退出后，音频
单独计数通过，但与 NNUE 并发仍溢出 2,736；此前有时钟初始化/退出负载的
raw 音频对照保留，不能直接作 RTL 因果结论。语音模型缺失、输入恒 −1，
完整兼容性与 TODO 仍未通过。精确状态见性能工程
`docs/YOLOv5n_LUT_Board_20261009.md`。

## 2026-10-09：层级剖析与小作业对照

同一 34,206 LUT 候选、已退出 GUI、CLINT、10 FEN、各 phase 200 次。原程序前后
冷 64.943/66.489 ms、热 61.542/62.365 ms；诊断关闭为 68.467/64.722 ms，开启
73.903/68.811 ms。诊断关闭也有编译布局/运行差异，开启增加 5.436/4.089 ms；
不能把诊断阶段值按比例缩放或当作无探针结果。原始计数在区间外换算，读计数/记账
10,000 对平均 20.031 us；视角、tile、job 和父子计时闭合，四组整数都通过。

诊断热样本 gather 完整调用 18.589 ms、FC0 submit 10.409 ms；CPU PSQ/threat 索引
7.934 ms、PSQT 6.724 ms、Stage A 用户态来回复制 5.864 ms，FC1 3.470 ms。
硬件作业 2.389 ms 属于提交子集；向量构造/零项更新等仍有 5.271 ms 未进一步细分。
不同尺寸 13 形状各 50 作业整数微测试中，dense 4×1（12 B shadow 复制）host
1.929 ms、硬件 0.004 ms；gather 2 项 host 3.933 ms、硬件 0.134 ms。
这说明小作业提交路径成本显著，不能将差值全归给复制或 syscall；该内核未启用 ftrace。

带宽实测。先观测内核细分，再尝试自主调度/PSQT 和中间状态驻留，并复核其他 fd 与模型。
基准每局面重置 accumulator，warm 只保留 feature cache；真实搜索的增量分布未测。

## 2026-10-14：先降资源，再重试高拥塞候选

远程 main 的 V3.5 S/Sv32 Pikafish 候选在 59.4 MHz 下整机 ADS 为
49,652 LUT、36,406 FF、4,468 LUTRAM、140 DRM、177 APM；一次布局的物理
CLMA 达到约 93% 至 95%。FP8 高、低两组共 128 个解码器，原布局报告
中叶模块合计 4,224 LUT，新 ADS 叶模块合计 2,539 LUT；叶模块差额
不能代替整机净节省。
无符号移位重写虽通过 256 种编码穷举和 MAC 定向回归，却让整机增加 130 LUT，
因此拒绝。改为先在 5 位有效数上处理符号，再作 18 位有符号移位，完整独立
ADS 两次获得 49,288 LUT（减少 364）、36,405 FF；LUTRAM/DRM/APM 不变。
256 编码穷举、MAC/SoC 定向回归、CPU ADS 控制和 7 项故障变异通过。
ICache 独立结构检查尚未绑定新输入快照；CDC 同版门槛、布局 CLMA、双角
STA 和板端测试尚未完成。映射节省不能推断布线或 CPU 时序已过。
另一个资源候选是 MAC 的 29-DRM 权重 bank：它缓存每次作业从 DDR 搬来的
1024×1024 位最大权重块，不是整份常驻模型。当前通用 S16 上限可用满
1024 条×128 B，而官方 Pikafish Stage B 的 U8S8 单作业仅需 64 条×128 B。
缩小该 bank 必须同时量化通用 ABI 是否收窄、分块重载次数、1024 位并行
读口所需物理块数、计算周期与整机映射；不能把 8 KiB 需求直接换算为 2 DRM。
来源：性能工程 `docs/Pikafish_Main_Integration_Candidate.md` 与本地 ADS 日志；
失败约束搜索仅作为反例，不作为可交付位流。

## 2026-10-14：多模型容量审查决定缩容边界

同一 dense MAC 的 1024 位权重行按 `ceil(Cin/4) × ceil(Cout/(packed?32:16))`
计数。Pikafish U8S8 256→32 只用 64 行，但 YOLO 的 S8S8 256→256 作业
可用 512 行；若把语音 `220→256→256→25` TDNN 从 CPU 搬到 MAC，三层
分别会用 440、512、64 行。原 S16S16 256→256 上限为 1024 行。
因而 64 行容量不是多模型通用方案。512 行缩容须在一次旧 ABI 提交内为
S16 大作业提供无损分段与原输出布局；1024 位并行读口能否真的节省 DRM
只能由独立映射及同版整机 ADS 证实。相邻 tile 的 DMA 复用也要算入
CPU 展开、作业提交和音频实时性，不能只看核心周期。
旧 VexRiscv 上 512 样本/16 kHz 音频 FIFO 与 NNUE 并发仍溢出 2,736
次；当前 Linux 驱动逐样本 MMIO 弹出并轮询。先测服务间隔与高水位，
再比较批量服务、FIFO 与独立 DMA，不能把加速 MAC 视作语音采集修复。
来源：性能工程 `docs/Multi_Model_Resource_Plan.md`、
`rtl/mac_accel/mac_accel_dma_kernel.v`、`docs/VOICE_CONTROL.md`；
这是设计审查，不是本候选的资源、物理或板端通过证据。

## 2026-10-14：单帧分时和按变化触发

棋盘图像功能目标可让一张冻结帧的完整 YOLO 图跨数千个 MAC 作业、
多个调度时间片执行；30 fps 是另一个性能阶段。每份张量和中间和必须
绑定同一帧 ID、模型代次及图依赖，完成三个 Detect 头后才输出 FEN。
作业边界让出物理引擎可以控制 Pikafish 等待及音频服务机会，但单帧
总 MAC 数、DDR 流量和端到端延迟不会因此自动下降；也不能据此缩小
最大单作业权重 bank。变化触发完整单帧可降低识别频次，须分别报告
相机采集率、触发率、识别结果率、变化到结果延迟及丢帧。格子裁剪或
跨帧缓存原 YOLO 中间特征需要独立模型/感受野与整盘黄金验收。
来源：性能工程 `docs/Multi_Model_Resource_Plan.md`、
`docs/YOLOv5n_Model_Integration_TODO.md`、
`docs/YOLOv5n_Xiangqi_Performance_Plan.md`。当前为设计核对，非整图板测。

在完整棋盘识别层面，还应比较全盘 YOLO、共享小型逐格分类器和
变化事件触发的全盘/局部复核。逐格模型的 MAC 数与识别质量须训练后
实测；90 个 crop 不能按单 crop 成本推断整盘。变化跟踪降低的是
平均推理次数，不能替代初始化、低置信度或漂移后的全盘兜底。
报告相机采集率、完整识别率、局面更新率及搜索响应四个不同指标。
来源：性能工程 `docs/Chess_Vision_System_Options.md`；尚无新模型硬件测量。

## 2026-10-16：分割分支与窄通道利用率

固定 320 输入比较 YOLOv5n-seg 的主体宽度、深度、mask 基数与 Proto 通道，
不能只按检测版或 width 平方推算分割成本。逐 Conv2d 形状统计与 MAC 理想
下界不包含 mask 合成、SiLU、DDR 或 CPU。NMS 后只为保留实例合成 mask，
其系数×prototype 另计。缩成 8/16 通道时，固定 32 输出通道的阵列会闲置；
比较多像素并行分发和权重广播后再决定加乘法器。窗口减少重复供数，不减少
同一模型的理论乘加数。30 fps 需不同输入帧、完整输出和有界队列；流水延迟
可超过单帧间隔，仍需报告 P95。来源：性能主工程
`docs/YOLOv5n_Seg15_320_Implementation_Plan.md`；尚无硬件性能证明。
