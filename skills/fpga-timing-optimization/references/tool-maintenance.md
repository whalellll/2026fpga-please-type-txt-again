# 交付时的时序优化工具维护（2026-10-21 用户要求）

本工程每次交付同时复核、维护本轮实际使用的时序工具，使路径分析和优化检查可以
在后续候选及独立解包环境中复用。优先扩展已有工具；本轮临时脚本中有复用价值的
能力应整理到正式源码入口，不能只留在个人工作目录或某个build目录。

## 维护范围

- 原生最终STA的corner/时钟对、WNS/TNS、setup/hold、skew和覆盖检查；保留原报告。
- 关键路径的起终点、逻辑/布线延迟、组合深度、扇出及新增长路径比较。
- 既有时序打拍、D/CE/时钟和级间边界，以及复制副本是否保留、消费者是否分组。
- 整机与模块资源比较，记录复制或拆级的开销；周期、延迟和吞吐证据分别呈现。

只维护与本轮问题有关的能力，不要求为每次交付重写工具或实现全部分析功能。
逻辑图深度、综合资源和工具自测不能替代原生STA或实板性能。

本工程现有入口示例（应用前核对当前文件、参数及适用范围）：

| 工具 | 用途 | 相关验证入口 |
|---|---|---|
| `scripts/microarch_timing_tool.py` | 微架构路径/Chisel线索分析；组合表达式复制；按具体规格生成逻辑修改或拆级补丁及隔离源码预览 | `scripts/test_microarch_timing_tool.py`；绑定原生路径回放；补丁适用性检查 |
| `scripts/timing_scope.ps1` | 原生时序范围、时钟与约束检查 | `scripts/test_timing_scope.ps1` |
| `scripts/profile_native_resources.py` | 绑定冻结输入的模块/整机综合资源剖析 | 绑定报告的实际数据重放及资源求和核对 |
| `scripts/audit_cpu_prepared_shift_ads.py` | 特定准备寄存器的实际映射检查 | `scripts/test_cpu_prepared_shift_ads.py` |

这些是项目路径，不是其它FPGA工程的默认工具链；新能力按实际需要复用或新增稳定入口。

微架构工具不仅维护报告检查：后续应维护分析与编辑的闭环，关联路径、单元/寄存器边界、
源码位置、复制/拆级方案、实际补丁以及验证要求。当前首版使用生成RTL层次和Chisel词法
线索，并非完整编译IR；支持有限组合表达式自动复制，任意单元拆级需提供完整控制编辑。
不得把源码候选、dontTouch意图或声明保留当作硬件副本、功能等价或最终时序改善。

## 每次交付的维护结果

记录工具入口、版本/commit或源码SHA256、依赖和运行命令；列出本轮新增/修复的问题，
以及对应run、网表/报告/输入哈希。无需改代码时记录复核范围和原因，不虚构工具改进。
修改解析器或审计逻辑时，用真实成功/失败报告重放，并为具体缺陷补充相关反例：
例如缺表、错误时钟、负slack、过期来源、未知驱动或副本被合并；未知数据不得猜成通过。
工具变更验证与硬件状态分开记录：已复核无需修改、已修改并验证、未完成/待验。

工具源码、实际使用的模块依赖、配置/说明及必要测试随交付保存；精简或匿名化的测试
输入应能复现缺陷，不把个人临时路径、完整PDS数据库或未接受位流当作默认依赖。
交付清单绑定工具与测试的哈希，独立解包后运行适用的自测和绑定报告重放，保存原输出
与结果。包外完成凭据再关联ZIP哈希，避免在ZIP内部写入其自身哈希。

在维护工作树中更新，不改写已冻结的原始报告或已封存交付包。若工具变化影响构建输入、
约束解释或硬件验收结论，按新候选完成相应验证；工具维护成功不构成硬件通过。
最后将可复用经验写入技能，运行skills review/verify，并同步项目与本机技能。

## 原生内部节点被优化后的审计维护（2026-10-21）

内部诊断名消失时先沿实际实例端口查明消费者，不能删除资格条件检查、把缺失节点
强制成常量或回写旧冻结run通过。综合器可把逻辑移出源码模块；局部模块端口也不能
被当作完整电路的任意独立输入。按实际向量/拼接/别名绑定层次，核对真实寄存器的
Q/D、时钟、复位和限定条件；未知驱动、未知位宽、组合环或证明资源上限一律拒绝。

本工程RsMem十位分类编码的检查器使用实际非队头发射重排寄存器作为消费者，
在明确的两项队列上下文中检查全部编码与ready/refresh/translation组合，并检查
非空可达使能，防止“恒不发射”通过安全断言。该组合上下文证明不是完整顺序等价；
仍需要逐拍差分、完整正确性、实际映射、最终全角STA与实板性能。维护入口为候选SoC
的scripts/audit_rsmem_hint_ads.py、ads_native_hier.py和对应原生故障/证据门禁测试。

状态压缩后测试空间的精确组合数可能改变。审计生产者与PnR前、最终证据及编程门禁
须一起支持明确的新表示、完整证明字段和依赖哈希，不能仅放松旧固定计数。
旧表示仍保留原检查。新检查器及传递依赖纳入新快照后重新综合；旧失败保持失败。
复用未改变的检查器或原生反例时按字节复制，避免文本换行转换破坏其来源哈希；
并发读取进度JSON对短暂未完成写入作有限重试，不把真实失败状态当作暂态忽略。

## 原生逻辑跨层移动、状态合并与资源检查范围（2026-10-22）

PDS可能将WB选择逻辑移出原源码模块，或将等价寄存器合并到另一层次。先核对本轮
原生删除/合并记录和真实连接；例如已注册的load WB tag不能误用未注册ROB完成tag。
按需要从真实消费者端到端证明选择、ready及优先级，保留物理FF/RAM边界之间的关系。
不要把经过mux/译码的中间信号任意切成独立变量：综合器可能已把其逻辑分配到另一分支，
这种切锥会制造不可达反例。未知驱动或无法绑定的删除节点仍应拒绝，不能猜常量。
若生产配置明确关闭一条写回通道，使用本轮原生常量删除证据说明实际活跃通道数；
全源RTL测试与配置后的原生证明分别报告，不能将前者改称全部通道的原生证明。

新增数据旁路或消费者副本后，旧单元检查器中的整机资源收益断言可能真实失败。
保留失败和实测开销，不能因局部寄存器/数据证明通过就宣称全部映射或资源门禁通过。
后续可明确区分原单元边界检查和新整机资源评估，但新评估必须独立绑定候选输入、
资源差值与已授权的性能/时序合同，不能通过移除旧全局断言隐去新增开销。

观察器应允许依赖控制器收据尚未创建的启动窗口，同时有明确超时；完成收据出现后
再调用只读报告展开入口。真实上游失败和超时保持失败。观察器失败不改变正式STA，
可在正式作业完成后用新记录恢复只读分析，核对原ADF、rtr/XML及冻结输入未改变。

## 收据格式扩展、间接依赖与源码预览（2026-10-22）

增加原生检查项后，为实际新observer提供明确的新格式入口，保留原始状态、run/VM及
CPU身份；不要伪造旧版“七项通过”的owner来适配旧交付工具。保留已有检查的语义，
补查新证明的完整位集合、非空使能、实际生产者、受保护寄存器和资源合同。使用真实
资源报告测试便携校验器时明确标记resource fixture，并用反例确认它不能通过native入口。
只检查收据及源码哈希的便携重验，不等于重新运行SAT、综合或最终STA。

工具直接依赖清单可能遗漏经sys.path导入的旧工程解析器。按实际导入顺序解析模块位置，
保存完整间接源码及哈希；原生检查开始前绑定，运行期间和结束后核对，独立副本使用
相对路径重验。不要为了打包而临时改变正在运行工具的导入顺序，也不把之后补做的来源
核对写成早先资源检查的新执行证明。不同频率报告的max-skew限值可能不同：旧阳性报告
按其原限值重放，新候选继续使用自己的严格限值，不能为了让旧报告通过而放宽新约束。

git apply --check只证明补丁可应用，不能发现Scala名字解析错误。逻辑重写删除定义后，
检查全部消费者是否仍引用旧标识符；布尔谓词穷举也不能替代完整Chisel编译、生成与输出
比较。发现预览缺陷时保留原预览与失败范围，另存修复版本；未编译/生成/测资源的预览
仍保持未验证状态，不混入当前已冻结的PnR候选。

## 打包位号与资源共享后的检查（2026-10-22）

PDS打包单元名中的数组位号未必等于所用Q输出的逻辑位号。结合原生详细报告的
实际pin、net及网表连接定位起点；不能只按实例名推断源码位。STOREPIPE失败路径
的物理实例带pdInsts_2[22]，所用Q网实际为pdInsts_2[0]。历史路径继续绑定原run，
新资源候选不能沿用旧候选的WNS作为自己的时序结果。

共享算术单元时，同时比较实际消费者的组合深度、边界寄存器和公共选择信号负载。
归一化布尔图的carry逐位深度、图内负载不等于物理逻辑级数或实际扇出；明确范围，
保留完整布线STA门禁。算术证明必须包含实际消费者仍使用的最低位，不能因为中间
加法器位被常量优化就猜测消费者常量；加入错误结果、错误位和不可达条件反例。

大量真实模块逐拍差分在解释式模拟器中过慢时，可换编译式仿真，但保留输入覆盖、
所有接口断言和独立输出oracle；记录引擎、二态/四态范围及复位/未初始化状态假设。
原未完成测试保持未通过，先在未修改的生产源码上跑通新测试，再验证实现改动。
测试编译或工具适配失败不算硬件功能失败，也不能计为通过或据此缩减覆盖。

## RAM读端口编号与跨层消费者（2026-10-22）

CIRCT/PDS的R0/R1编号不保证对应源码的第0/1提交槽。按真实RAM primitive的RADDR
各位及连接关系建立逻辑槽位映射，并证明低位地址来自对应head；例如本轮Fwd RAM
R0实际读取odd head、R1读取even head。根据端口后缀猜槽位会制造错误反例。
数据整形逻辑也可能被提升到Commit等真实消费者；沿实际消费者检查，不能把被提升
的中间mux任意当作独立输入。活跃配置删除的mem2通道与全源RTL优先级测试分别报告。

旧解析器若拒绝实际合法的escaped层级RAM输出名，先保存原失败和源码，隔离扩展
明确需要的标识符字符集；保留常量初始化、输出宽度、literal位号及重复驱动拒绝。
同时测试普通/escaped阳性和未知位号、未知初始化、错误宽度及重复输出反例。
先在未改生产逻辑的真实父网表验证写入及消费者模型，再用于新候选；未知驱动仍拒绝。

整机综合可能在未改源码的其他模块重新分配LUT/Carry。比较原生模块与整机实测，
不能把整机差值直接归因于一条XOR或假设共享加法器必然节省固定数量单元。
独立资源试验和组合候选分别绑定run/VM/CPU身份；本轮独立前端Carry316→228，
组合候选为316→288，不能混写。布尔图边界深度及负载、实际物理延迟分别记录。

十一项原生检查可复用原九项语义函数并在内存中传入明确的九项子集，但不得篡改
原始observer状态或写出伪造九项收据。保留新增算术/元数据完整位集合、可满足条件、
真实RAM地址映射、时序FF和容量核对；用实际资源报告反例确认资源收据不能变为原生。
独立副本复核收据与完整导入来源后，仍明确它没有重新运行SAT或代替最终STA。
