# 固定提频流程

## 当前性能、发布与交付后归档规则（2026-10-23 用户要求）

以下是本工程后续版本的常规流程，覆盖下文历史总分不降、包先于推送及逐次打包要求；
不将该工程的0.05阈值或G:/H:盘符作为其他工程的默认值。

- **CoreMark只限制每MHz效率。** 对同轮、相同工具链和工作量的全部合法实板样本，
  比较CoreMark/MHz均值，控制组减候选值最多0.05；不另设总分不降、总分降幅或总分最低值。
  保留总分及变化作为观测，预算内下降如实披露。实际频率、每次至少10秒、官方CRC、
  正确性及既定官方模型/并发门禁继续有效。新校验器不得重引入总分拒绝条件；旧冻结
  校验器及失败回执保持历史身份，重放时区分历史合同与当前验收结论。
- **先测试成功，再推送，再制作版本交付包。** 实现按变更范围通过完整正确性、必要的
  最终全角STA及实板功能/CoreMark/MHz/官方模型/并发验收后，提交并推送已授权目标
  （本工程为main），回读远程commit及来源/RTL/运行产物哈希；随后制作该成功版本的
  正式包。冻结、本地开发、每次代码修改、失败/中断/待板测候选和单独文档或skills维护
  均不要求制作交付包；仅推送流程文档也不触发硬件版本打包。失败实现不得混入main。
  用户明确要求的诊断导出单独标为未验收资料，不冒充正式交付。
- **完成包验证才宣布交付完成。** 包含已推送的精确实现及完整配套SD启动文件、技能库和
  来源清单；独立解包回归、实卡部署/回读及直接SD启动与应用验收仍须完成，并保存绑定
  最终ZIP哈希的完成凭据。推送不代替包验收；维护性文档更新不要求重打已封存版本包。
- **每版交付后释放G盘过程占用。** 以版本/commit、ZIP哈希和完成凭据为归属，检查真实
  活动进程、Git/worktree、引用、后续增量构建及回退/复现需求，生成明确文件清单。
  将后续用不到的重复打包/解包树、编译/仿真缓存、临时中间产物，以及已确认无需继续
  使用且可恢复的综合/布线中间数据库归档至`H:/fpga_archives/<版本>/`。逐文件核对大小
  与SHA-256，保存原路径、归档路径、归档哈希、释放字节数和恢复命令后，才移除对应G盘副本。
  不按目录名称/时间猜测归属，不普通移动Git worktree，不清理活动作业、未完成候选、
  唯一源码/模型/用户数据或仍需回退的运行文件；保留已接受位流/SD包、原生报告及测试证据
  的可验证恢复入口。交付前和本轮仍待验的目录不据此自动迁移。
  不需要重复请求已授权的常规归档许可。H盘不可用、空间不足或校验失败时保留G原件并
  记录待归档，不改放F盘；先恢复H条件再继续。历史清理脚本若仍默认归档到G，先适配H目标
  并验证再Apply，不能用G盘内归档冒充释放G空间。没有可迁移项时记录范围及原因。
  完成后更新目录索引和交接；不回写旧封存包、旧原生失败或原始哈希。

## 每轮提频的资源优先判断（2026-10-21 用户要求）

本工程每轮提频均检查完整布局布线后的原生最终 STA：若目标 CPU 域最差
WNS < −0.5 ns，下一步先考虑优化资源占用。记录 run、冻结输入、原报告哈希、
corner 及 setup/hold 类型；中间估计、未完成或过期报告不代替该轮最终结果。

先比较整机及相关模块的 LUT、FF、LUTRAM、块 RAM、DSP 占用，结合拥塞、扇出
和关键路径的逻辑/布线延迟寻找可削减的冗余或共享机会。记录资源优先评估和
下一步选择依据；不能仅由负 WNS 断言资源就是根因。资源改动仍须核对实际配置、
完成正确性和性能检查，并以实际映射数据证明收益，再比较新的最终全角 STA。
不能用连续换 seed、放宽约束或牺牲官方加速器性能代替该评估。

−0.5 ns 是每轮触发资源优先考虑的阈值，不是最终验收线；最终受约束路径仍须
无负 slack。本轮先前约定的“下一轮最终 CPU setup WNS < −0.1 ns 时先优化资源”
继续适用，不因新增通用规则放宽为 −0.5 ns；保留既有失败证据及已触发的资源优化记录。
这些阈值为本工程用户指定，迁移到其他工程时按其性能合同确定。

## WNS触发资源优化时保留时序打拍（2026-10-21 用户补充）

因最终WNS < −0.1ns而转入资源优化时，目标是减轻资源与布线压力，同时保持
已有时序优化。用于切断长组合路径、提前准备控制/数据、隔离大扇出的打拍寄存器、
级间边界和必要复制/缓冲必须保留，不把这些资源当作可裁剪冗余。
本条限制撤销已有打拍，不撤销先前在性能预算内新增打拍的授权。

修改前从冻结源码与实际综合网表记录受保护的寄存器及D/CE/时钟、消费者和路径，
区分功能存储与时序隔离资源。优先在这些边界以外寻找冗余逻辑、位宽或存储映射收益。
共享读口、合并mux/仲裁、收拢控制或改变RAM/DSP映射时，检查是否串接了原先分开的
组合逻辑、汇聚消费者或形成新的长路径/大扇出，不能以少了多少LUT/FF单独决定取舍。

新候选在实际网表中核对受保护边界仍有效，未被绕过、吸收为组合旁路或扩大为
单点驱动；比较相关路径的逻辑级数、扇出负载、逻辑/布线延迟及受影响的新起终点。
发现新增长路径或大扇出时先修改或拒绝该候选，不能凭功能等价、周期相同或资源下降
宣称不影响时序。综合与布局前估计仅作筛选，保持原时钟及约束，以同条件最终全角
STA核对时序；完成前保持待验，最终全部受约束路径仍须无负slack。

## 时序优化优先缩短组合链、降低扇出（2026-10-21 用户补充）

优化时序时优先分析压力路径的组合长度与扇出，再依据实际逻辑/布线延迟选择修改。
资源与拥塞可控时，允许复制组合逻辑、寄存器或必要控制副本，使各副本就近驱动
不同消费者；允许将同一逻辑链甚至整个单元拆成两级，在两级之间设置有效流水边界。
这是本工程用户明确允许的优化方向，无须为普通候选实现再次确认；历史案例中的
不增加流水限制不覆盖本条。已有打拍保护、WNS触发的资源优先流程继续适用。

复制前记录原驱动及消费者分布，比较整机LUT/FF/RAM/DSP、布线和时钟/复位/使能负载。
在实际综合及布局网表中确认副本未被合并、消费者确已分组，且未把高扇出转移到新的
公共选择或使能信号。不能仅以源码出现两个副本认定扇出改善。

拆级时选择能平衡两级实际延迟的边界，同步保存数据、控制、有效位和事务身份；
更新依赖该单元的ready/valid、背压、转发/相关性、flush、异常和复位行为。
先以参考模型按事务核对结果及事件顺序，验证两级保持、停顿、取消、连续事务和
完整回归，再测响应延迟、启动间隔、总周期和实际工作量吞吐。新增流水候选不能
继续无条件使用旧版逐拍输出相等断言，也不能忽略新增等待或改变运算语义。

新增副本或流水级的资源开销必须实测且可容纳，局部组合缩短不等于整机时序通过。
检查两级各自及新控制路径的setup/hold、扇出和布线延迟，在原频率/约束下运行最终
全角STA。沿用当前性能合同：本工程同轮CoreMark总分只记录、每MHz均值绝对下降
最多0.05，官方加速器性能不退步；仿真周期仅作预筛，实板性能仍须单独验收。

## 提前译码的原生捕获等价检查

在既有指令寄存边界提前保存窄译码结果时，按 FF 的真实 Q 连接定位，不能假定
实例名等于信号名；PDS 可能增加 `_vname` 后缀。核对全部状态位、时钟和使能。
PDS 也可能把译码合到输入选择器前后，不能把源码中间网当成独立输入来检查 D。
应比较完整原生元数据 D 与实际指令 FF D 的译码结果，使用经过独立标量/反例
验证的严格组合等价方法；未知依赖、无法支持的单元和规模上限均应拒绝。

CPU75 86c9992 案例使用有节点上限的 ROBDD，支持实际普通 LUT 和专用 mux，
在 127–187 个任意布尔源上证明八位 D 捕获等价。仍需逐拍接口检查保持流水
周期和吞吐。合并后消失的命名控制从真实消费者及故障捕获 FF 的 D 端绑定，
并保留旧的全部功能向量、独立反例和旧结构对照；双输出 LUT 的无效 cofactor
须消去后才能唯一定位返回选择器。原生拒绝记录不改判，新审计及依赖加入
冻结输入，以新快照重新综合。通过这些门禁仍不代表最终 STA 或实板通过。

## 结构检查通过后的路径迁移

CPU75 第十轮在原 ALU 发射沿准备 PC+4，原生写回输出组合扇入中的 carry
每路 30→0，且完整 108 项 CPU、23 项 SoC、十组 Windows 检查通过；实际
整机 FF −1,476、LUT +154，RAM/DSP 不变。正式全角 STA 仍因 CPU setup
−0.656 ns、32 端点失败而拒绝，最差路径转为 PD 指令选择/return 判定到
预测更新目标，路由占 82.259%。因此原生 carry 数或组合级数只能作为诊断，
不能外推出 WNS 改善，也不能继承前一轮的通过角或端点数。
保留同一 run 的全部 116 行 summary 和失败路径，再决定是否在既有 FC→PD
边界提前保存窄元数据；新增状态需精确逐周期对照及原生资源检查。

这是可迁移的方法。工具、器件、构建控制、CPU 来源和编程规则以当前工程为准；
历史案例不授予任何新 PnR、JTAG、SD 或 Flash 操作权限。

## 九个门禁

1. **基线和目标。** 记录提交、生成配置、器件/速度等级、工具、时钟、约束、
   位流/固件/报告哈希，以及实际 CPU 与模型成绩。分别定义总性能、每 MHz 效率、
   吞吐、延迟、资源和并发指标。一个时钟域提频不等于其他域的算力同步增加。
2. **路径和资源诊断。** 从最终报告记录 corner、时钟对、起终点、逻辑级数、
   路由占比、扇出和偏斜。逻辑深度、路由拥塞、存储映射和时钟错误分别处理。
   提频收益小或资源压力大时，先测量并减少资源/连接压力，再继续提频。
3. **隔离冻结。** 使用新目录，固定 CPU 来源、RTL/IP、固件、ROM、约束、
   seed/hold 参数和工具，生成哈希清单。统一时钟意图到 PLL、约束、软件和 DTB。
   同步检查 IP 内嵌时序标注及映射后的真实时钟源，不能只核对 FDC 文本。
4. **正确性及综合。** 实现前编写精确输出和周期检查，完成受影响的功能回归。
   检查 CPU/ROM、缓存/MMU/TLB、总线、加速器整数语义、权重和 CDC。
   审核 LUT/FF/RAM/DSP/PLL 容量及实际保留结构；保持模型功能、带宽和吞吐。
5. **受控完整 PnR。** 记录目的、输入哈希、结果、单作业超时、进程归属和停止方法。
   当前工程已删除累计次数/期限、预留名额及豁免规则；历史只记录，不阻止新运行。
   无正确性/资源/ADS前置门禁不启动PnR。
   工具退出码、原生错误、同一综合输入及物理约束实际生效均须核对。
6. **最终全角和覆盖。** 使用最后一次修复后的正式 STA，检查所有要求的
   setup/hold/recovery/removal/pulse width、时钟对、max delay/skew 及每 bit 路径。
   无缺表、空端点组或负余量；审查 exceptions、no_clock、I/O delay 和传播假设。
   报告及位流绑定同一构建。零已约束违例不等于完整板级时序覆盖。
7. **启动契约。** CPU_HZ 与 CPU、TIMEBASE 与实际计时域一致；核对 bootloader、
   OpenSBI、DTS、保留模型内存、MMIO 范围和实际后端。DMA/未缓存访问遵循平台粒度，
   处理尾字节不跳过完整性校验。确认实际驱动/直访模式，不能只信配置名称。
   将硬件 MMIO 解码与所有 RAM bank 求交；本例 CLINT 位于 RAM 地址范围内，
   需要 reserved-memory/no-map 排除，避免 shadow 分配映射到控制寄存器。
   本工程每次交付必须整合最终SD启动包，完整记录从解包部署到Linux和应用启动的命令、
   文件、时钟与哈希；这些正式包步骤在实板验收通过并推送后执行。独立解包后实卡回读
   并从SD启动验收。临时RAM辅助启动仅作诊断，
   不能代替该门禁；具体要求见板端技能的“本工程Linux交付启动门禁”。
8. **实板验收。** 按当前授权核对器件，加载哈希一致的候选。实测 CoreMark
   三次性能加一次正确性，各至少 10 秒、官方 CRC 及计时通过；不用 RTL CoreMark
   代替板上性能。要求不回退时做同会话同工具链/工作量 A/B，报告波动。
   同时核对实际模型、权重、DMA、多个 fd/进程/线程、mmap 复用隔离、DDR、音视频
   和长时间系统响应。失败需保留现场并恢复，不能以某个微基准通过覆盖失败。
9. **记录与发布。** 每轮保存身份、资源、最终余量、覆盖缺口、实际结果及未测项。
   测试成功后先推送已授权目标并回读，再制作并验证该版本交付包；开发/失败/待验过程
   和单独流程维护不逐次打包。交付完成后按本页当前规则校验归档到H并释放G副本。
   更新文档和技能，review/verify，再随交付附完整技能库和关联清单。
   每次交付同时复核并维护本轮时序分析/优化工具，保留源码、依赖、版本/哈希、
   测试和维护记录，独立解包验证；步骤见[时序工具维护](tool-maintenance.md)。
   Git 保存候选可包含失败状态；生产发布必须全部满足本地发布契约，不能混称。

## 有效信号与宽数据寄存器使能

如果关键路径落在宽数据寄存器的 CE，先检查接口是否只在 valid 时消费数据。
仅在无效拍的保持值不属于接口契约、所有消费者均受 valid 保护时，才可评估每拍
捕获 payload。valid、仲裁、阻塞、异常、flush 与 owner 的输出和周期必须保持。
对照测试始终比较控制/owner，在有效拍精确比较 payload，覆盖满/空、回绕和竞争。
从生成源修改并成对生成 RTL；原生 ADS 逐 bit 确认 CE 实际消除，再看最终物理结果。

75 MHz 案例第二轮的 ALU1→redirect PC CE 为 25 级、WNS −0.254 ns，未上板。
第三候选上述逐周期对照及全部 100 项 CPU/23 项 SoC 功能检查通过，原生 ADS
确认 32 位 PC 从 GTP_DFF_E 变为不带 CE 的 GTP_DFF；最终却是 setup −0.733 ns、
hold −0.001 ns，不能把结构改善当作时序通过。数据每拍切换也需按项目要求评估动态功耗。

第三轮最差路径为 DCache→LSU 默认 store 数据旁路→MDU 保留站，路由占 86.546%。
下一候选化简被顶层 DC 返回选择支配的默认分支，内部 store 状态/STQ 不变。
先通过原版整块逐周期对照，再通过优化后 103 项 CPU/23 项 SoC 检查；综合 LUT
再少 51。原生部分命名 WB 位的 dcReturn 组合深度从 4/5 级降到 2 级，仍需最终
PnR/板测。保持值也有契约时必须连无效拍一起精确比较，不能暗中改变接口。
原生综合可能合并信号和端口；保留失败的旧名检查并按实际结构限定新检查范围，
不能把缺失位、抽样位或 PnR 启动后的审查追认为全位启动前证明。

## 实际频率、时序目标与周期展开

CPU75 第四轮数值 STA 全满足（setup +0.433 ns，hold +0.143/+0.103 ns），但
check_timing 的 unexpandable_clocks 从 0 变为 1，完整构建仍被拒绝且没有上板。
PDS 的 1 ps 量化使 13.333 ns /20.202 ns 的公共周期超出 1,000 周期。
后续候选保留实际 675 MHz/9、75 MHz 和软件时间，仅收紧 STA CPU 周期到
13.320 ns，CDC 29 条延迟/偏斜限值从 12.533 收紧为 12.520 ns，原时序例外不变。
主机数学/生成器/负例通过，只说明新契约可展开，原生 PnR/覆盖/板测仍需重验。
不能为了通过而把新问题计数加入旧豁免，也不能将更严格的约束频率当作实测频率。

进一步检查发现完整 SYS FDC 字面值仍是 20.202020 ns，仅对报告显示值计算 GCD
不充分。首个收紧候选在 PnR 前主动停止综合，完整次数没有增加。增加混合精度
负例，把 SYS STA 字面值也微幅收紧到 20.202000 ns（真实 SYS 保持 49.5 MHz）；
完整字面值与 CPU 13.320000 ns 精确在 91/60 周期相等。12 项 CPU75、12 个 PLL
ADS 夹具、32 项生成器/负例及 23 项 SoC 功能通过，新的原生构建仍待验收。
不要把输出格式的截断精度误当作工具内部算法精度，数学充分条件仍需原生确认。

第五轮原生 check_timing 确认 unexpandable_clocks 回到 0，但 setup −0.223 ns、
两个端点仍失败，不能上板。精确网格修正解决的是时钟展开，不能继承第四轮的
正数 setup 余量。384 个硬件/IP/固件输入及原生 LSU 模块均相同，约束变化仍需
重新完整物理验收。

反序/原始输入、符号和移位量，隔离移位消费者的扇出和选择。不能把增加寄存器
